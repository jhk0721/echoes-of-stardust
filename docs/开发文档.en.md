## 0. Project Positioning

**One-liner**: You play the last "Stardust Listener", traveling across memory planets on the brink of extinction. Help memories fulfill their final wishes, then play a dirge to send them into stardust.

**Core gameplay**: Weaving combat — play four notes, listen to expose weaknesses, reproduce rhythm patterns to trigger Resonance, and improvise a finale with three spirit rhymes.

**Aesthetic principle**: Pure black cosmos + light in the dark. **All assets are procedurally generated — zero art dependency** — this is the project's fundamental answer to "bad art skills" (see §3).

## 1. Technical Architecture (80/20 Split)

| Layer | Technology | Share | Responsibility |
|---|---|---|---|
| Engine & game logic | Python + pygame | 80% | Scenes / UI / story / battle flow / asset generation |
| Judgment core | C++17 shared library (DLL) | 20% | Beat judgment, sequence batch judgment (performance-critical) |
| Bridge | ctypes (native/bridge.py) | - | Auto-degrade to a pure-Python equivalent when the DLL is missing |

**Why this split**: The game is mostly narrative + state machines + procedural drawing, where Python's development velocity crushes C++. Beat judgment, meanwhile, runs every frame on a latency-sensitive path, and "game feel" needs constant tuning — C++ keeps it fast and clean. The bridge layer guarantees it runs even without a compiler.

### C++ build (optional, when a compiler is available)

```bash
cd native
cmake -B build
cmake --build build --config Release
copy build\Release\rhythm_core.dll .
```

After building, bridge.py automatically uses the cpp backend; without the DLL, run `python -c "from native import bridge; print(bridge.load())"` and it will print `python`.

## 3. Asset Acquisition Strategy (Best Answer to Bad Art)

**Principle: procedural fallback + free asset enhancement, unified style, zero copyright risk.** Pipeline:

1. **Fonts**: stitched pixel font Fusion Pixel (OFL-1.1) `assets/fonts/`, 10px simplified-Chinese proportional as primary, 12px monospace fallback; falls back to system font chain if missing.
2. **Particles**: Kenney Particle Pack (CC0) `assets/particles/` transparent version — star, flare, spark, smoke, trace, magic families all included; title-screen stardust and battle effects are all particle-driven.
3. **UI**: Kenney UI Pack Pixel Adventure (CC0) `assets/ui/` 533 items, pending nine-slice button/panel integration.
4. **SFX**: Kenney UI Audio (CC0) `assets/audio/kenney/` 56 items; click/rollover already replaces procedural UI sounds.
5. **Planet rendering**: GLSL shader (`native/planet.glsl`, hash noise / warm-cool tint / HDR tonemap modeled after blackhole.glsl). Runtime dual-track: moderngl real shader preferred; automatically degrades to pure-Python per-pixel translation (identical results) without GPU. Unified upper-left light source → all planets share consistent lit/shadow orientation for a strong sense of order.

**Asset list (installed 2026-08-15)**: fusion-pixel three font versions, Kenney particle-pack / ui-pack-pixel-adventure / cursor-pixel-pack / ui-audio, OGA Platformer Art Pixel Redux + Deluxe, real harp PNG (pngimg.com harp_PNG12, 409×784 transparent, CC BY-NC 4.0, non-commercial only; deprecated on title screen, kept for battle scene), 8 procedural exclusive memory planet PNGs (`tools/gen_planets.py`, `assets/sprites/planet_0~7.png`).

**Note**: after changing assets run `python tools/generate_assets.py` to regenerate (`ensure()` only generates when missing; manual run does a full overwrite). Drop new assets directly into the corresponding `assets/` dir; code scans by path.

## 4. Core System: Weaving Combat

### 4.1 Input Mapping
| Key | Note | Color | Effect |
|---|---|---|---|
| J | Wind | Pale teal | Horizontal cutting arc, knockback |
| K | Fire | Orange red | Flame burst, burn |
| L | Water | Azure | Wave push, slow |
| I | Earth | Ochre | Shockwave, bind |
| U (hold) | Listen | - | Time slows to 30%, exposes enemy rhythm |
| Space | Improvised finale | - | Requires 3 spirit rhymes |

### 4.2 Resonance Judgment (core in C++)
- Every enemy has a rhythm pattern (note sequence + beat interval), e.g. Shadow Beast `wind-fire-wind @460ms`
- Per-beat judgment: `Judge.press()` uses a 150ms window to check timing; the window is adjustable in `rhythm.py`
- Hit → double damage + spirit rhyme +1 + resonance sound + white flash; miss → normal damage only
- Judgment implementation: `native/rhythm_core.cpp::step()` (C++) / `bridge._py_step()` (fallback) — **the two must stay isomorphic**

### 4.3 Sequence Rules (finale.py)
- Identical neighbors → unison, +50% strength
- Opposite neighbors (wind/earth, fire/water) → counterpoint fusion: steam mist / sandstorm
- Notes after a rest → 2x damage
- 8-slot fill, 5-second composing time, ESC to cancel

### 4.4 Enemy Data Repo (extension point)
Add an entry to `ENEMIES` in `rhythm.py` to add a new enemy:

```python
"void_singer": {"name": "Void Singer", "notes": ["water","earth","water","fire"],
                "gap_ms": 400, "hp": 90},
```

## 7. How to Run

```bash
pip install -r requirements.txt        # skip if installed
python run.py                          # first run generates assets + sets MX150
python tools/smoke_test.py             # headless loop self-check
python tools/story_test.py             # story full-flow self-check
```

Controls: title ↑↓/mouse to select menu, Enter to enter; in story Enter advances dialogue, S skips node, ESC back to title; in battle J/K/L/I play, U listen, Space finale, WASD move.
